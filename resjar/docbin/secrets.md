# Secrets & Rotation

This repo does **not** use a secret manager (no sops-nix / agenix). Server
secrets are generated on the host at runtime and kept **out of git and out of
the nix store**. This document lists where each one lives, how to read it, and
how to rotate it.

> [!IMPORTANT]
> These files live only on the host. Back them up (or you will lose the
> ability to decrypt/migrate the services):
> `/var/lib/authentik`, `/var/lib/outline`, `/var/lib/outline-ssl/`.

## authentik (`sysset.server.authentik`)

Generated by the `authentik-env` oneshot (`juajar/sysjar/server/authentik.nix`)
**only if the file does not already exist** (`ConditionPathExists=!<file>`).

- **File:** `/var/lib/authentik/env` (mode `0600`, `umask 077`, root-only)
- **Vars:**
  - `AUTHENTIK_SECRET_KEY` `openssl rand -base64 60`
  - `AUTHENTIK_BOOTSTRAP_PASSWORD` `openssl rand -hex 12` (akadmin first-boot password)
  - `AUTHENTIK_BOOTSTRAP_TOKEN` `openssl rand -hex 30` (API bearer token for the outline OIDC provisioner)
  - `AUTHENTIK_BOOTSTRAP_EMAIL` the declared `adminEmail`
- **Read:** `grepauth` alias, or
  `sudo grep AUTHENTIK_BOOTSTRAP_PASSWORD /var/lib/authentik/env`
- **Set your own password:** create `/var/lib/authentik/env` yourself (with the
  four vars) **before** authentik's first start the unit only writes it when missing.
- **Rotate:** delete the file and restart the service. Note the bootstrap vars
  are only read on authentik's **first** start, so on an existing instance
  change the password in the UI instead; changing `AUTHENTIK_SECRET_KEY`
  invalidates sessions/signing keys.

## outline (`sysset.server.outline`)

- **OIDC client secret:** path set by `extraConfig.oidcAuthentication.clientSecretFile`
  (whale uses `/var/lib/outline-oidc-secret`, mode `0640 root:outline`). It is
  written by the `outline-oidc-provision` unit, which creates the authentik
  OAuth2 provider/application and handles the restart.
  - **Re-run:** `sudo systemctl start outline-oidc-provision`
- **App keys:** auto-generated at `/var/lib/outline/` on first boot.
- **TLS (self-signed, outline 1.9's secure-cookie requirement):**
  `/var/lib/outline-ssl/cert.b64` and `/var/lib/outline-ssl/key.b64` (paths set
  via `extraConfig.sslCertFile` / `sslKeyFile`). Swap for real ACME certs when a
  domain lands.

## Not secrets

- `hstjar/<host>/net.nix` holds **public** SSH host keys + LAN IPs (fleet pinning, not secret).
- `usrset.name` / `usrset.email` (per-host `user.nix`) are the git identity, not credentials.

## Why not declarative?

The server modules intentionally bootstrap secrets so a **first boot is
hands-off** (no manual secret provisioning step in the installer). If you later
want them in git, sops-nix or agenix can be added and the `clientSecretFile` /
`environmentFile` paths repointed at the decrypted secret paths.
